# Proof rules

A release needs evidence proportional to its claims, not a fabricated readiness
or virality percentage.

| Label | Meaning |
|---|---|
| DOCUMENTED | A current primary source states this platform behavior |
| LOCALLY_TESTED | This exact command/artifact was tested in a recorded environment |
| USER_OBSERVED | An actual external user performed a task; scope and consent recorded |
| HYPOTHESIS | A plausible interpretation or planned experiment |
| UNKNOWN | No adequate evidence yet |

Record: claim, scope/version, source or test, outcome, date, caveat.
No invented timing, testimonials, compatibility, install count or search demand.

## Stranger-first use

Use a temporary clean directory. Read commands and dependency hooks before any
execution. An install test may require network and must respect host permissions.
Never borrow maintainer private credentials to make a demo pass.
Record prerequisites, exact command, first useful output and recovery path.
A successful file copy is not an end-to-end agent behavioral test.

## Public snapshot

Explicitly select files; review licenses and attribution, images, logs, config,
personal paths, screenshots and embedded private data. A heuristic text checker
cannot replace media review or a real secret scanner. Review Git history when
publishing existing history. Prefer a new approved snapshot when appropriate,
without destroying the original repository or hiding required provenance.

## Checker limits

The supplied Python helper is a limited, read-only hygiene check. It reports
locations without echoing matched credential values. It does not certify the
project as secure, compliant, useful, well ranked, or likely to go viral.
It ignores named build/cache/private-work directories, does not read Git history,
and does not validate every Markdown form or YAML feature. Review its reported
scope. Do not silently ignore its warnings before a public release.

## Growth claims

5,000 stars is an aspiration unless observed on the actual repository.
A literature review or another repository's success is not personal growth
experience. Do not say "battle-tested" based on this package's local tests.
